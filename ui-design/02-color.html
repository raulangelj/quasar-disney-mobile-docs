Decision 2 — Color

Four palettes for the two surface modes the theme must carry (doc 02, decision 9 / DF4): the dark app mode and the light auth mode. Each option below shows the same storefront screen and the same credentials-with-error screen, so what you are comparing is only color.

Contrast ratios are computed, not estimated. Every text pair shown meets WCAG 2.1 AA (≥4.5:1) in all four options — that is a floor I applied while choosing values, not a differentiator between them.

Held constant across all four (decided later, neutral for now): system sans typography and one type scale · 4 pt spacing rhythm · tile radius 10, sheet radius 22, pill CTA fully rounded · bottom tab bar · placeholder art geometry. The brand wordmark is drawn as text here only because the real QC+ SVG isn't inlined in this scratch page.

Two findings that apply whichever you pick: (1) the cyan/indigo accent cannot carry white text as a button fill (2.1:1 and 3.0:1 — both fail), so accent stays a progress-bar / link / active-state color and pill CTAs on dark stay white-fill-with-black-label, exactly as the reference does it. (2) The reference's dimmest greys (inactive tab icons, “11 min restantes”) land at ~4:1, so I raised the tertiary text floor to ≥4.5:1 in every option.

Option A — Reference Cyan

recommended cool neutral · closest to reference

Neutral-cool near-black (#0E0E12, the value transcribed from the reference home screen) with a sky-cyan accent. Zinc grey ramp — no hue in the neutrals, so placeholder art colors never fight the chrome. Tradeoff: it is the most Disney+-like of the four, which is the goal here but also the most lookalike exposure (RISK-0005 is about the name, not the palette).

Option B — Deep Teal

brand-cohesive · tinted neutrals

The welcome screen's teal gradient is pulled through the whole system: near-black is teal-tinted (#0B1215), the grey ramp is teal-tinted, the accent is a brighter aqua, and even the light-mode link is teal instead of blue. Most cohesive as a brand — one hue family everywhere. Tradeoff: tinted neutrals cast a green-blue wash over warm placeholder art, and it drifts furthest from the transcribed reference values while still reading as the same product.

Option C — Neutral Indigo

most distinct from the reference

Same cinematic structure, but the accent moves off cyan to indigo and the auth gradient goes indigo-navy. Pure-neutral zinc greys. Why consider it: cyan-on-near-black plus a teal auth gradient is arguably the most recognizable part of Disney+'s palette; indigo keeps the craft and drops that association. Tradeoff: the cyan progress bar is a named element of the reference transcription — swapping it is a visible fidelity concession, and indigo at AA-safe brightness sits closer to the violet placeholder art, so tiles and chrome compete slightly.

Option D — True Black

max art pop · OLED

Option A's hues on a pure #000000 ground, with a more vivid accent and slightly brighter greys to compensate. Artwork appears to float; on an OLED device it is the punchiest of the four. Tradeoff: pure black loses the "slightly lifted from black" quality the reference actually has, translucent chrome over #000 shows banding on lower-end Android panels, and the placeholder-art bottom scrims were authored against a lifted near-black, so tile edges disappear into the background.

Semantic ramp — same in all four options

not a differentiator

Success / warning / error / info are decided once, independent of which palette you pick, because Phase 1 barely uses them: the only semantic color on a shipping 1a screen is the auth error. The rest exist so the token set is complete and a later toast/empty-state doesn't invent hexes. Note: on the dark surface the semantic colors need to be lighter than their light-mode counterparts — same role, two values, which is exactly what the two-mode token structure is for (criterion A1).
