OptionRule
AFixed pt widths. Simple; peek is accidental and differs per device.
Bwidth = W × 0.42. Responsive, but the magic fraction encodes no intent and rounds badly.
Cwidth = (W − gutter − gap×(v−1)) / v with v = tiles visible per variant: 1.9 landscape, 3.6 portrait, 1.15 hero. The peek is the spec, so it holds at every width.

C also gives the Container config a natural home for the number — one more field beside variant, which is what DF6 asks for anyway. Heights follow from the locked aspect ratios, so nothing else needs measuring.

10 · Safe areas, orientation, font scaling

recommended

The hatched red bands in the frames above are the unsafe regions. Because decision 7 chose headerShown: false, these insets are ours — nothing else will pad for the Dynamic Island or the home indicator.

TopicDecisionWhy / consequence
Device range375–440 pt wide phones, iOS and Android. No tablet layout, no foldables.375 is the narrowest current phone; the strategy above degrades gracefully below it rather than breaking. Tablets would need a second grid nobody will show on 18 Aug.
Safe areasSafeAreaProvider + useSafeAreaInsets(); top inset padded by AppHeader and AuthSheetLayout, bottom by the custom tab bar.Applied at those three components only — not sprinkled per screen — so a screen never double-pads. The overlay and loading gate use the same provider.
OrientationPortrait locked both platforms (plist UISupportedInterfaceOrientations, manifest screenOrientation="portrait").Every reference screen is portrait, and landscape carousels are a different grid. Locking it is one line per platform; supporting it is a second design.
OS font scalingHonored, with maxFontSizeMultiplier caps: 1.6 on body and above, 1.3 on caption, 1.2 on micro.Uncapped, a 200% accessibility text size turns the tile metadata block taller than its artwork. Caps keep chrome legible without ignoring the setting outright — see decision 11.
Pixel densitySVG art and icons scale freely; PNG wordmarks ship @1x/@2x/@3x.Follows from the react-native-svg decision.

15 · Platform conventions — where we follow, and where we deliberately don't

A visual-fidelity demo has a standing tension with platform convention: iOS HIG and Material disagree, and the reference is an iOS app. The rule I'd apply: follow platform convention for behavior, follow the reference for appearance. Behavior is what users' hands expect and what breaks if you fight it; appearance is what the demo is being judged on.

AreaCallDetail
Back navigationfollow platformAndroid hardware/gesture back and iOS edge-swipe both pop the stack (decision 7). Non-negotiable on Android.
Press feedbackdeviateMaterial expects a ripple; we use scale + opacity uniformly (decision 6) so the two platforms match in the side-by-side. Recorded as a deliberate deviation, not an oversight.
TypographydeviateBundled Inter on both rather than SF Pro / Roboto (decision 3) — same reason.
Status barfollow platformlight-content in both modes: the app is near-black, and the auth sheet sits below a dark gradient, so the bar is over dark pixels on every screen. Translucent on Android.
Keyboardfollow platformKeyboardAvoidingView with behavior="padding" on iOS and "height" on Android — they genuinely need different values. The auth sheet must keep the CTA reachable with the keyboard up; that is the one layout the keyboard can break.
Tab barfollow platformBottom tabs are native to both. Unlabeled icons match the reference; Material would prefer labels, but iOS tolerates icon-only and the reference is icon-only.
Alert on card tapfollow platformRN Alert renders each OS's native dialog. Since it is a placeholder for navigation (DF7), native is exactly right — no custom modal to throw away in Phase 2.
Splash / app iconfollow platformStatic launch screen from qcplus-mark on both; no animated splash library. Icon from the same mark.

Android 15 (targetSdk 35) enforces edge-to-edge. System bars become transparent and content draws underneath them whether or not the app opts in — so the safe-area handling above is not polish on Android, it is the difference between a correct screen and a title sitting under the status bar. Worth knowing before Saturday, since RISK-0003 already flags the scaffold as the top schedule risk and this is exactly the kind of thing that eats an hour at the wrong moment.
